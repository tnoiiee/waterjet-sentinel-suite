## 1. Purpose and authority

Stage 0.3A moves the proven Stage 0.2.1A spike outcomes into the product tree: contracts,
domain skeleton, a simulator-only runtime foundation, kiosk placeholder, config examples, and
the enforcement tooling — **as sources first, validated by the Owner on their workstation**.
Nothing here is authorized by convenience; every authorization traces to the Owner's Option-C
amended Scope Gate and is re-checked at each substage boundary.

## 2. Hard boundaries inherited (non-negotiable)

1. **Simulator-only.** `deviceProfile` is `SIMULATOR` in every committed example and every
   default; production device access is `[NOT AUTHORIZED]` at any stage 0.3A substage
   (ADR-0012; ADR-0014 §4).
2. **Offline.** No CDN, no remote packages at runtime, no Internet assumptions in any path;
   loopback `127.0.0.1` is the only address that may appear in the product tree (rules S1/S2
   of `tools/boundary-scan`).
3. **No protected-doc dilution.** `docs/` decision records and `docs/spikes/**` are historical
   evidence; 0.3A may *reference and extend* them, never rewrite their meaning.
4. **Compile-before-claim.** No .NET artifact is reported as building/testing until the
   Owner-local run in [`STAGE_0.3A_OWNER_LOCAL_VALIDATION.md`](STAGE_0.3A_OWNER_LOCAL_VALIDATION.md)
   returns PASS, verbatim, into the PR.
5. **Fixture honesty.** Committed fixtures are `PROVISIONAL STRUCTURAL FIXTURE` until
   regenerated by the .NET generator (ADR-0014 §6).

## 3. Goals of Stage 0.3A

1. `Wjss.Contracts` becomes the single authoritative wire contract (snapshot, delta, command,
   status, queue entry, config types) with a TypeScript structural mirror and golden fixtures.
2. Domain skeleton (states, sensor identity, queue model) exists as *code with tests*, not
   prose.
3. `apps/runtime` boots to a health endpoint against the simulator adapter — loopback only.
4. Config example files exist in `config/examples/` and are schema-checked by tests.
5. `tools/boundary-scan` mechanically enforces the repository/product boundary (exit 0).
6. Kiosk compiles as an inert window (0.3A-1 only; behaviour comes at 0.3A-4 per ADR-0016).

## 4. Explicit non-goals

- No production transport implementation, no UI build pipeline, no chart rendering, no
  historian persistence, no alarms, no auth — those are 0.3A-3..-6 / later stages.
- No WebView2 reference, no new NuGet/ npm packages beyond the approved minimum set.
- No lockfile fabrication, no CI definitions in 0.3A-1. The `global.json` prohibition held
  while no build had ever run; at the 2026-10-07 closeout the Owner directed pinning the
  validated SDK (`10.0.401`, `rollForward: latestPatch`) and committed the twelve genuine
  restore-generated lock files via handoff — both are Owner decisions recorded in the

- No spike deletion/move; no ZIP archive until Stage 0.3 exits (Owner rule).

## 6. Contract boundary rules

- Records live only in `packages/contracts/Wjss.Contracts`; UI mirror is structural, C# wins
  disputes (ADR-0014 §1).
- Delta semantics: sparse fields; `activeJob` three-state (absent = unchanged / object =
  replace / explicit null = clear) via the scoped `Optional<T>` presence technique;
  `gap`-style revision jumps ⇒ client re-snapshot, never a repair attempt.
- Sequence-record ordering normative (ADR-0014 §5); queue head-only consumption, capacity 8,
  refusal `409 QUEUE_FULL` (ADR-0014 §3).
- Every wire change = contract PR with fixture regeneration + TS validator update + boundary
  scan in the same commit.

## 7. Queue model implementation rules

Contiguous positions 1..N, capacity constant in `QueueRules` only; enqueue appends at N+1
(rejecting `> 8`); dequeue shifts survivors and bumps the batch revision by 1; edits are
per-entry revisions. **Open decision (deliberately `[OPEN]`, do not code either way yet):**
*queue eligibility* — whether a point enters the queue at the moment it is marked dirty, or
only after the Runtime's authority checks pass (operator permission, interlock state). The
question originates from [`QUEUE_MODEL.md`](QUEUE_MODEL.md) and needs an Owner ruling before
0.3A-2 freezes the enqueue path. This checkpoint keeps both readings out of the contract:
`QueueRules` validates *shape*, the *policy* hook is a domain interface with no implementation.

## 8. Configuration and examples

`config/examples/*.example.json` (2 files, structure-only, `SIMULATOR`) + `PublishedConfig` /
`SensorMap` contract records + `Wjss.Config.Examples.Tests` schema guard. Production values
never enter the repo (boundary scan S3). Secrets: ADR-0011 governs; nothing in 0.3A-1 reads
or stores any secret. **No `appsettings.json` is committed at 0.3A-1** — the Runtime reads
only code defaults; the settings-file pipeline (including the `REPLACE-ON-CUSTOMER-BOX`
historian-connection placeholder convention and the loopback `applicationUrl` override) is
introduced with its schema in 0.3A-3.

## 9. Simulator adapter

**0.3A-1 state:** the project is the seam only (csproj + rules README, no behaviour). The
canonical deterministic sensor topology (18×6 wall map, 106 sensors, 2 cannons), synthetic scan
order and TC channel mapping currently live in the shared generator
(`tests/integration/FixtureGenerator.cs`), which the future adapter will reuse rather than
duplicate. **0.3A-2 scope:** seeded acquisition inside the adapter, tick-based state evolution,
injectable faults (gap, stale, refusal). Determinism is a hard requirement either way: same
seed ⇒ same fixture bytes — this is what makes `FixtureParityTests` meaningful.

**0.3A-2A state (Checkpoint A):** `adapters/simulator/Synthetic/` now supplies the canonical
synthetic map (`SyntheticSensorMap`: 108 slots / 106 Sensors / 2 Cannon slots at logical I7 and
I16, row-major scan order, device distribution 14 + 14 + 13 × 6, `SYN-TC-nn:CHmm` channel
identities) and the seeded initial Sensor projection (`SyntheticSeed`,
`DeterministicValueSource` — splitmix64; no `System.Random`, no static mutable state). The
project depends only on `Wjss.Contracts` and `Wjss.Time`, so the Runtime composes its first
revision from a SIMULATOR source without any application-layer reference. A runtime-side parity
test pins the map composition to the committed `config/examples/sensor-map.example.json`.

**Deferred, not silently diverged:** the "reuse rather than duplicate" consolidation between
this source and `tests/integration/FixtureGenerator.cs` is `[OPEN]` — the fixture-side
provisional formulas are untouched in 0.3A-2A, and the Runtime's synthetic values are
seed-derived presentation values, deliberately **not** claimed equal to the fixture generator's
`ScoreFor` formula. Seeded tick evolution, quality/classification evolution and fault injection
remain Checkpoint B scope.

## 10. Runtime API and health

In 0.3A-1 the Runtime exposes exactly two
routes: `GET /api/v1/health/live` (200 once the host is up) and `GET /api/v1/health/ready`
(503 `RUNTIME_NOT_IMPLEMENTED` — the honest "not ready yet", the only readiness statement
allowed until 0.3A-2). The state snapshot, stream and command routes — with the refusal
matrix (bad payload 400 / queue-full or occupied 409 / unsupported 501) — are the 0.3A-2/3
scope; contract shapes for them already exist in `Wjss.Contracts` and the fixtures.
