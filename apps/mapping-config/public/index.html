Process-image evidence review read-only · no address is entered or overridden here

Model RackSlot IO-CHECK Pos. ProcessModulePosition Role Process data Width in / out (verified) Profile state Evidence source Diagnostic / status byte Actual-rack evidence ProcessImageOrder Address state Reason Profile fingerprint

Four different things are kept in separate columns and are never used for each other: RackSlot is the physical slot from the authoritative workbook and includes the Power Supply and End modules; IO-CHECK Pos. is the position of the same physical module in the actual-rack configuration-tool sequence; ProcessModulePosition is the ordinal among modules that contribute Application Process I/O data only; ProcessImageOrder is the order used by the process-image rule and is NOT_VERIFIED in this Stage. A Power Supply, the System Power Supply and the End Module contribute no process data: their address reads NOT APPLICABLE with reason NON_PROCESS_DATA_MODULE, and they are not waiting for an address. A numeric address is derived only from verified evidence; otherwise it stays ADDRESS_UNRESOLVED.

Actual-rack evidence read-only · partial · instance and Channel scoped

Instance Model RackSlot IO-CHECK Pos. Channel Evidence state Displayed type / version Visible settings Applies to

Actual-rack evidence is instance-level. A setting verified for one Channel of one module is not evidence for another Channel, another instance of the same model, or another model. It never feeds address derivation: the actual Process Data image and the head-station I/O Config are still missing, so every address stays ADDRESS_UNRESOLVED and the derived candidate stays CANDIDATE_UNVERIFIED. No Hardware, Polling or Write control exists here.
