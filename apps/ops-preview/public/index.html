      Motion Commissioning read-only design and commissioning state · NO HARDWARE ACCESS / NO MOTION COMMAND

      The Application-owned manual motion commissioning foundation: the four motion controllers (one per WSB cabinet), the sixteen controller axes, the eight Water Jet axis allocations, the brake output plan and the limit input plan, with the Application-owned authorization gate. Every value is a status or a logical identity: nothing here is read from a device, no controller endpoint is configured, no controller library is installed, no controller is connected, no axis is homed, no software limit is commissioned, no brake state is read and no motion command has been issued. The authorization gate is CLOSED and every motion intent is refused before any hardware path is reached.

      The axis role is always written as Horizontal Axis or Vertical Axis. The physical controller axis letter (A, B, C, D) may appear only as diagnostic identity beside the role, never instead of it: Horizontal Axis · A. Values are published in controller units: no counts-to-millimetre conversion is verified, so no value is shown in millimetres and no Legacy value has been promoted to configuration.

      This section is the static motion commissioning catalogue. It is served by the dedicated read-only route /api/motion-commissioning/catalogue and is deliberately carried by neither the Runtime Snapshot nor a Runtime Delta: it does not change with a revision, so it is not re-sent with every Snapshot. The Snapshot stays reserved for dynamic observed motion state, none of which is authorized in this revision.
