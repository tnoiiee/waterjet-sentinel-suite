## Delivery model

| Rule | Spike behaviour |
| --- | --- |
| Authority | The Node harness owns all operational state. The UI owns only selection and view state. |
| Revision | One monotonic integer per published state. Every Delta carries `previousRevision` and `revision`. |
| First message | Every SSE connection (initial or reconnect) starts with a full `OperationalSnapshot`. `Last-Event-ID` is ignored. |
| Delta content | Only changed Sensor records (whole-record replacement) and changed singletons. Absent key = unchanged; `activeJob: null` = cleared. |
| Gap | `previousRevision !== current revision` → the UI applies nothing, closes the stream, and reopens it to get a fresh Snapshot. |
| Reconnect | Full store replacement. No Delta replay, no command replay, no inference from the stale cache. |
| Slow client | A client whose socket buffer exceeds the bound is closed; it reconnects and receives a Snapshot. |
| Commands | HTTP POST, token protected (`X-Spike-Token`), never queued or replayed by the UI. |
| Folding | 212 Thermocouple channels (`TC_F`, `TC_R`) are folded into 106 `SensorPresentationState` records in the runtime. |

## GlobalQueue and dispatch (Owner domain correction — synthetic, NOT Production scheduling)

The GlobalQueue holds **ready-to-dispatch entries only**; presence in the queue means READY.
There are no `BLOCKED`, `HELD`, `WAITING_*`, `EXCLUDED`, `INVALID`, `OUT_OF_SERVICE`, `DISABLED`,
`BAD`, or `STALE` entry states. A Sensor that is not dispatchable is not in the queue. Per-Sensor
`queueState` is `NONE` / `QUEUED` / `ACTIVE`. AutoSequence pause and pump / Water Jet / valve /
pressure / pre-check waits belong to the Active Job or the AutoSequence, never to queue entries.

| Rule | Synthetic runtime behaviour |
| --- | --- |
| Capacity | At most 8 unique entries physically (`QUEUE_FULL` beyond); no `slice(0, 8)`, no hidden queue |
| Dispatch | Only Position 1 is a candidate (no scan-forward). One atomic step removes the head entry, creates exactly one Job targeting that Sensor, and writes one `DispatchRecord` (queue revision +1) |
| Active Job | At most one; dispatch is refused (`ACTIVE_JOB_EXISTS`) while a Job is active; after it ends only the new head is a candidate |
| Review controls | Never retarget a Job; "Review Job" first makes the Sensor the queue head, then dispatches the head |
| Eligibility | Not implemented. Admission refuses only Water Jet slots, duplicates, the Active Job target, and capacity. `eligibilityDiagnostics` lists `NOT_ADMITTED` Sensors only when a test scenario sets them; reasons are pending the Owner-approved policy ([decision matrix](../../../docs/spikes/queue-eligibility-decision-matrix.md)) |

The previous synthetic queue / job behaviour (per-entry status, scan-forward auto start,
unbounded queue with an 8-row preview) is **SUPERSEDED** and **NOT ELIGIBLE FOR PRODUCTION
PROMOTION**. The schema identifiers (`wjss.spike.snapshot/1`, `wjss.spike.delta/1`) are unchanged:
the stream is transient spike output with no persisted consumer.

## Sensor map (Owner domain correction)

106 Sensor locations and 212 Thermocouple channels; walls Left 24 / Rear 29 / Right 24 / Front
29; an 18 × 6 logical matrix with Cannon slots at logical I7 (`CANNON_REAR`) and I16
(`CANNON_FRONT`). The validator checks every Sensor record and every wall-map slot against the
canonical map: positions, wall, scan order, device, `TC_F` / `TC_R`, 212 unique channels, and
the two Cannon slots. It rejects a Cannon ID used as a Sensor and a `wallMap` in a Delta. The
superseded 104 / 208 baseline (`SYN-<WALL>-NN`) is no longer produced. Scan order, device
distribution, channel identifiers, and the Water Jet / Isolation Valve assignment are synthetic.

## Classification and quality (approved spike rule)

- Dirty Score > threshold → `DIRTY`; ≤ threshold → `CLEANER`. The threshold comes from the
  Synthetic Published Configuration.
- `UNCERTAIN` keeps the last validated classification (`classificationBasis: LAST_VALIDATED`);
  a new uncertain value never changes it; with no last validated value → `NOT_CLASSIFIED`.
- `BAD`, `STALE`, `DISABLED` → `NOT_CLASSIFIED`.

All synthetic values are labelled **SYNTHETIC SPIKE PARAMETER — NOT A PRODUCTION VALUE**.
